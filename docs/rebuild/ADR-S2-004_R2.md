# ADR-S2-004-R2 — Entity-Owned Configuration Module for the SYLPHY Entity Runtime

**Status:** Accepted (implementation executed under the S2-004-R3 implementation task, authorised by the Project Owner's approval of the S2-004-R2 architecture decision)
**Date:** 2026-11-25
**Task:** S2-004-R3 — Entity-Owned Configuration Implementation
**Governing authority:** `SYLPHY_MASTER_PLAN_FUTURE_HANDOVER_v3.0.md` (Version 3.0)
**Prerequisite audits:** `docs/rebuild/S2-004_R1_STARTUP_CONFIGURATION_AUDIT.md`, `docs/rebuild/S2-004_BLOCKING_EVIDENCE.md`, `docs/rebuild/S2-004_ACCEPTANCE_EVIDENCE.md`

## Context

The SYLPHY Entity production startup path failed at runtime with:

```
NameError: name 'load_config' is not defined
```

with traceback frames `src/sylphy_entity/daemon.py:main:97` → `src/sylphy_entity/daemon.py:_run:30` (`config = load_config()`).

Source inspection established that:

1. The only definition of `load_config` in the repository is `src/sylphy/config.py:83` (Legacy application package, `AppConfig`).
2. `src/sylphy_entity/daemon.py` contained no import of `load_config` and no local definition — the production configuration seam was unresolved.
3. The intended chain was: `config.toml` → `load_config()` → `config.identity_file` → `EntitySupervisor(identity_file=...)` → `EntitySupervisor` → `load_identity()` → `ConversationRuntime` → `_respond()`.

The S2-004-R1 audit confirmed this and proposed two viable architectures (Alternative A: Entity-local identity configuration module; Alternative B: shared/consolidated configuration module) and rejected adding a direct Legacy import into the Entity daemon because it would conflict with the Entity–Legacy isolation requirement.

## Decision

**Alternative A was adopted** (as recommended in the S2-004-R1 audit and approved by the Project Owner): create an **Entity-owned configuration module** at `src/sylphy_entity/config.py`, keep the Legacy `src/sylphy/config.py` unchanged, and have the Entity daemon consume the Entity-owned configuration loader.

## Decision details

### 1. Entity-owned configuration module

- New module: `src/sylphy_entity/config.py`.
- Exports: `EntityConfig` (typed, explicit configuration object with `identity_file: Path` and `config_file: Path`) and `load_entity_config(path: Path | None = None) -> EntityConfig`.
- Does **not** import `sylphy.config`, `sylphy.identity`, or any other Legacy runtime module.
- Does not duplicate the Legacy `AppConfig` surface; it implements only the configuration contract required for Entity startup and Identity path resolution.

### 2. Identity path precedence (implemented)

The Entity-owned loader resolves the Identity path with:

1. `SYLPHY_IDENTITY_FILE` (canonical Identity environment variable) — wins when both Identity environment variables are set.
2. `SYLPHY_ENTITY_IDENTITY_FILE` (backward-compatible alias) — used only when the canonical variable is unset.
3. Top-level TOML key `identity_file` in the Entity configuration file.
4. `identity_file` key in the `[ollama]` table of the Entity configuration file.
5. Default `identity.toml`.

The Entity identity loader (`src/sylphy_entity/identity.py`) resolves, when no explicit path is supplied, the canonical variable first and the legacy alias second.

### 3. Behaviour preserved

- Relative Identity paths remain relative to the process CWD (no silent absolutisation).
- Missing Identity file behaviour is preserved: deterministic fallback identity (`fallback_default=True`) in the Entity loader.
- Missing configuration file is explicit: `load_entity_config()` raises `FileNotFoundError` when the resolved configuration file does not exist.
- Legacy `src/sylphy/config.py` remains the configuration owner for the Legacy application; no changes were made to it.
- Entity–Legacy import isolation remains enforced (no Entity → Legacy configuration or Identity imports).

## Consequences

- The production daemon startup path now resolves configuration through the Entity-owned module and passes the resolved Identity path into `EntitySupervisor`, which loads Identity through the Entity-owned loader.
- The production startup no longer fails with `NameError: name 'load_config' is not defined`.
- Long-term there remain two configuration owners: the Legacy `AppConfig` (broad application surface) and the Entity-owned configuration module (Entity startup seam). Consolidation (Alternative B) remains an open architectural option.
- The single canonical Identity environment variable is `SYLPHY_IDENTITY_FILE`, with backward compatibility for `SYLPHY_ENTITY_IDENTITY_FILE`.

## Implementation (S2-004-R3)

- Created `src/sylphy_entity/config.py` (Entity-owned configuration module).
- Modified `src/sylphy_entity/daemon.py` to call `load_entity_config()` and pass `config.identity_file` into `EntitySupervisor`.
- Modified `src/sylphy_entity/identity.py` to prefer the canonical `SYLPHY_IDENTITY_FILE` and fall back to `SYLPHY_ENTITY_IDENTITY_FILE`.
- No changes were made to `src/sylphy/config.py`.

## Consequences for the governing plan

- Entity startup now uses an Entity-owned configuration seam; Entity → Legacy dependency remains absent.
- The end-to-end production identity chain (`Entity-owned config → EntitySupervisor → Entity identity loader → ConversationRuntime`) is implemented and now requires runtime verification (see implementation report).
- Phase 2 acceptance must be decided by the Project Owner after independent review; this ADR records the approved architecture decision only.
